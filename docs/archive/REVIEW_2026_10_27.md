# JIT-D (`jitd-final.zip`): independent review and improvement plan

Reviewed 27 Oct 2026. Hackathon deadline: **30 Oct 2026, 10:00 AM PDT (10:30 PM IST)**. About three days remain.

## 0. Read this first

**I cannot promise "no flaws can be found."** Any reviewer, judge or competitor can find something in any project. What you can do is make sure that (a) every flaw you know about is either fixed or disclosed right next to the claim it affects, and (b) nothing a judge will hit in the first five minutes is broken. This plan is built for that.

**Overall judgment.** The engineering and honesty are well above typical hackathon work: 182 tests pass, the secret scan is clean, the docs state their own limits, and the paired study publishes a negative result. The project is currently weakest on exactly what the judges score: **no real Nemotron evidence, a broken demo video, a hosted-demo bug I reproduced, a README that buries the story, and a core evaluation whose "independent" evidence is not independent.**

My rough, unofficial estimate of the four equally weighted criteria (judgment, not measurement):

| Criterion | Now | Reachable in 3 days | Main lever |
|---|---|---|---|
| Technological Implementation | 6/10 | 8/10 | Live Nemotron evidence, fix hosted bugs, rigorous stats |
| Design | 7/10 | 8/10 | Clean README, playable narrated video, 3-minute path |
| Potential Impact | 4.5/10 | 6.5/10 | Honest cost model, real-drift evidence, one real workflow |
| Quality of Idea | 5.5/10 | 7/10 | Sharper claim against real prior art |

## 3. Evidence and statistics

| ID | Flaw | Why a reviewer will care | Fix | Done when |
|---|---|---|---|---|
| **E-01** | **Confidence intervals treat runs as independent.** Wilson intervals use the pooled count of post-onset runs across all seeds (`bench.py`, `post_runs = sum(cnt.values())`). Runs inside one stream are correlated, so intervals like 0/2257 look far tighter than the evidence supports. | Pseudoreplication is a classic statistical objection. | Make the stream (seed) the unit. Report per-stream rates, a cluster bootstrap over streams, and a Clopper-Pearson or Wilson interval on streams where it makes sense. Rewrite every "k/n" headline. | README quotes stream-level results and no interval narrower than the stream count justifies. |
| **E-02** | **The AAIR benchmark has only 3 seeds × 60 runs and no intervals.** | Headline "180/180" is three streams. | At least 30 streams per cell (the legacy bench already does 30). Add intervals as in E-01. | AAIR cells report streams, per-stream spread and intervals. |
| **E-03** | **The "independent" authority and the oracle share fixture truth.** The strict path blocks correlated drift because the simulated authority is derived from the same truth the oracle uses. This is disclosed, but it means the headline win holds by construction. | It is the core claim of the redesign. | Add an **authority-error sweep**: the authority is wrong, stale or itself drifting with probability ε (and a scenario where the authority drifts together with the provider). Plot silent-error rate and false-block rate against ε. State the result as "safe if the authority is at least this reliable." | A figure and table show where the guarantee breaks. |
| **E-04** | **Scenario authorship bias.** Contracts, hypotheses and scenarios were written by the same people. | Self-built tests flatter the method. | Have one outsider write 5 to 10 new drift scenarios without reading the contract code (the repo supports external JSON). Add a generated drift family (parameterized units, filters, ordering) with held-out parameter ranges. Report results before any code change. | Independent scenarios are in `benchmark/external/` with `"independent": true`, and results are published as they came out. |
| **E-05** | **Modelled agent baseline is assumed perfectly correct.** "Repeated reasoning has 0 silent errors by assumption" makes any silent-error comparison with an agent meaningless. | Unfair in the agent's favour on correctness, unproven on cost. | Run a real Nemotron agent baseline on a small set (for example 50 invoices): real tokens, latency, accuracy. Report its actual silent-error rate. Label everything else as modelled. | One table has measured agent rows beside modelled ones. |
| **E-06** | **No ablation matrix.** | Reviewers ask which component earns its place. | Ablate: declared contracts only, mined only, authority off, diagnosis off, repair off, checkpoint reuse off. Report effect sizes with E-01 intervals. | A single ablation table in `docs/EVALUATION.md`. |
| **E-07** | **Thresholds are hand-set.** The ×3 range margin and 0.01 tolerance were never swept. | "Tuned on your own data" objection. | Sweep each threshold, plot false-block vs miss, and show the chosen point. | One sensitivity plot per threshold. |
| **E-08** | **Weak baselines.** The comparison does not include cache-plus-fallback (real prior art, see R-01), a model-as-judge verifier, a statistical data-validation baseline, or a contract-test baseline. | Judges from NVIDIA and Nebius will know these. | Treat **naive replay as the Stagehand/Skyvern-style baseline** (replay, fall back only on failure) and name it so. Add a Nemotron-as-judge verifier baseline and a simple statistical-drift baseline. | The headline comparison includes at least these two extra baselines. |
| **E-09** | **No real drift corpus.** All drift is injected. | "Is this a real problem?" | Build a small corpus from public API changelogs and OpenAPI diffs. Count how many changes are structural, how many are semantic and would pass a schema check, and run the verifier on the semantic ones it can express. Cite primary sources. | A table of N real changes with classification and outcome. |
| **E-10** | **Timing and "savings" language.** Timings on an eight-step in-process graph do not show customer speed. | Overclaiming. | Keep the existing disclaimers. Remove any dollar figure not paired with its assumptions on the same screen. | Every number shows measured, modelled or simulated beside it. |

## 4. Research rigor and novelty

| ID | Item | Action | Done when |
|---|---|---|---|
| **R-01** | **The core mechanism already exists as shipped features.** Stagehand's docs describe caching agent actions, replaying them with no LLM calls, and re-inferring when the recorded selector stops resolving. Skyvern's docs describe recording successful actions as reusable code and falling back to the agent when the cached code fails because the page changed. | Say so in the README and position the contribution narrowly: **verification-gated acceptance of cached replay when nothing visibly fails.** From the pages I read, their documented fallback triggers are execution failures; I did not find silent-meaning-drift detection described there, but that reading is not exhaustive. Verify before you assert it. | The prior-art table names these systems and states exactly what differs. |
| **R-02** | **The problem is real, but cite carefully.** Several vendor and blog sources describe silent provider changes that keep returning 200 OK, and one integration vendor says contract tests do not catch same-schema, different-meaning changes. Some blogs quote large drift percentages (for example "41% within 30 days") from secondary sources I could not trace to a primary study. | Cite only primary or clearly attributed sources. Do not quote the percentages unless you find the study. Prefer your own E-09 corpus. | Every external statistic has a primary source or is omitted. |
| **R-03** | **Precise problem statement and falsifiable hypotheses.** | Write three hypotheses with success and failure thresholds before running the final experiments (for example H1: with an authority of reliability ≥ X, silent errors ≤ Y per stream). | `docs/EVALUATION.md` lists hypotheses and whether each was supported, refuted or inconclusive. |
| **R-04** | **State the safety property formally.** | "The sink executes only if every required assumption is VALID against fresh, independent, snapshot-consistent evidence." Add property-based tests (for example with Hypothesis) over random event orders, stale evidence, retries and checkpoint corruption, plus mutation tests that deliberately weaken the gate. | The property is in the docs and a generated test suite fails when the gate is weakened. |
| **R-05** | **Generality is unproven.** One workflow, eight steps, two repair types. | Implement one second workflow from a different domain on the same operation set (not a new framework), or clearly state the scope limit. Do not add a GNN or new subsystems. | Either a second workflow with the same evaluation, or a scoped claim. |
| **R-06** | **Keep the negative result.** The paired study shows ordinary dependency replay matches semantic slicing here. | Keep it prominent. It is a strength. Remove "assumption-aware" novelty language from titles. | No heading implies a superiority the data does not show. |
| **R-07** | **Cost model must include people.** My economics check showed that at roughly $0.001 per agent run, one held run reviewed by a person costs more than the model call saved. | Add a break-even analysis: the agent cost per run above which replay-with-verification wins once review time and hold rate are included. Use measured Nemotron token costs from E-05 for the agent side. Claim savings only above that threshold. | A figure or table shows the break-even and where your measured workload sits. |
| **R-08** | **Reproducibility.** | Add one command (`make reproduce` or a script) that rebuilds every table from raw data. Keep source fingerprints. Add a `docker build` step to CI. Archive results with a release tag. | A clean clone reproduces the headline tables with one command. |

## 7. Security and robustness

| ID | Item | Action |
|---|---|---|
| **X-01** | **No Content-Security-Policy.** Only `nosniff` and `Referrer-Policy` are set. | Add `Content-Security-Policy: default-src 'self'; frame-ancestors 'none'` and `X-Frame-Options: DENY`. Move any inline script or style needed into files. Test in a browser. |
| **X-02** | **Client escape helper skips the apostrophe** (`esc` handles `& < > "`). Safe where attributes use double quotes, fragile otherwise. | Escape `'` too and add a test that renders hostile strings through every `innerHTML` template (about 27 uses). |
| **X-03** | **Rate limiting keys on `request.client.host`.** Behind a proxy every visitor shares one address, so the limit either throttles everyone or protects nothing. | Key on the authenticated token or a trusted forwarded address. Test with two simulated clients. |
| **X-04** | **Worker isolation has a timeout but no memory or CPU limits.** The docs say it is not an OS sandbox. | Add `resource` limits (CPU, memory, file size) on POSIX, a Windows job-object equivalent or a documented skip, and a test that a runaway validator is killed. |
| **X-05** | **Dependency and supply-chain checks.** | Add `pip-audit` to CI and keep `requirements.lock` current. |
| **X-06** | **Token hygiene.** | Rotate any key used for live runs after the evidence is committed. Confirm `evidence/` contains no headers or keys (extend the secret scan to cover it). |

## 10. Do not do

- Do not add a GNN, a second framework, SSO or multi-tenancy now.

- Do not edit evidence files after they are generated.
