# JIT-D Studio — submission narrative

**Reason once. Verify what matters. Recover cheaply.**

JIT-D connects a bounded invoice-agent builder to evidence-gated execution and reviewed recovery. A user describes a supported
task, inspects its typed template and parameters, validates fixed cases, publishes an approved version, and runs it. A schema-valid
unit change can trigger a halt before acceptance. A bounded repair is inspected through captured-input replay, checked against
fresh strict evidence, separately reviewed and retried. Missing authority evidence remains blocking.

The implemented model roles are Architect (bounded draft parameter proposal) and Repairer (allowlisted repair). Model configuration,
a reply, an accepted bounded proposal and a promoted repair are distinct observations. Receipt source/usage and fallback labels
remain visible. No actual paid NVIDIA/Nebius result is bundled; it must be collected with the entrant's configured access.

## Three-minute demonstration

- 0:00–0:20: explain the valid-JSON dollars/cents problem and one supported user task.
- 0:20–0:45: create the bounded draft, inspect model/template provenance, and show an unsupported task refusal.
- 0:45–1:05: inspect tests, publish the exact content with a separate reviewer, and run a clean invoice.
- 1:05–1:30: apply unit drift, show the block, compare schema-only replay and inspect the passport.
- 1:30–2:10: inspect a real model repair receipt when available, captured-input impact and fresh strict checks; separately approve and retry.
- 2:10–2:30: show recorded usage and human review declarations. Label any cost sensitivity curve as assumptions; do not call it measured savings.
- 2:30–2:50: remove authority evidence and show UNKNOWN halt, then show that a saved draft edit clears validation eligibility.
- 2:50–3:00: close with the bounded scope, known limits and next external validation.

Use current release checks, not old test counts. Historical research remains synthetic; ordinary dependency replay can match or
outperform semantic reuse, and correlated wrong authority can certify wrong output. No general compiler, universal safety,
production financial integration, research novelty or winning prediction is asserted.

Actual NVIDIA-on-Nebius evidence, independently controlled cases, a clean Windows execution, a public licensed repository,
judge-accessible demo/test build, public narrated demonstration and the applicable submission materials remain external gates.
The historical synthetic video is not the new Studio/live-model submission video. Only present functionality and evidence that
actually work in the submitted release.
